### Reproducibility

`packaging/verify-repro.sh` made two signed `--strict` builds:

- Build A used the normal Go build cache.
- Build B used an **empty `GOCACHE`**, so everything was recompiled.

Each build started from deleted `dist/pyre-v0.1.0-rc1-*` directories. All 16
binaries matched byte for byte (`cmp` of the `dist/SHA256SUMS` lines), and so
did all 6 release files: 4 tarballs including their SBOMs, `SHA256SUMS`, and
`SHA256SUMS.sig`. Ed25519 signing is deterministic. The final
`release.sh --strict` run into `dist/release/` was byte-identical to build A
for all 6 files.

Linux binaries are statically linked ELF (x86-64, aarch64). The darwin
binaries are Mach-O (arm64, x86_64) with only the linker's ad-hoc signature:
they are not Developer ID signed or notarized.

### Verification failure paths

- **`packaging/test-release-integrity.sh --release dist/release`: 13/13
  passed.** It re-signs copies of this release's `SHA256SUMS` with throwaway
  keys and runs everything in a scratch HOME.
  - Accepted with a warning while nothing is pinned: an unsigned release, and
    a signed release whose signature cannot be checked.
  - Exit 3 with `current` unchanged: a tampered `SHA256SUMS`, a signature by
    another key, a missing signature once a key is pinned, a wrong key even
    with `--allow-unsigned`, an `--allowed-signers` that conflicts with the
    pin, and a `--from` directory while pinned.
  - A good signature passes and pins the key.
  - Limitation: the passing cases re-stage the installed version (already
    current). The version switch itself is covered by the WP20 install
    rehearsal.
- **`go test ./internal/updates -run 'SSHSig|Signed|AllowedSigners'`: pass.**
  - The pure-Go SSHSIG verifier accepts real `ssh-keygen -Y sign` output, and
    `ssh-keygen -Y verify` accepts the test-built format.
  - The verifier rejects:
    - a tampered message
    - another key
    - a namespace or principal mismatch
    - a flipped signature byte
    - garbage input
    - cert-authority-only, RSA-only or malformed allowed-signers files
  - `pyred`/`pyre` staging, from a local file or over https, refuses each of
    the following while a key is pinned and leaves no payload:
    - a tampered `SHA256SUMS`
    - a tarball replaced after signing
    - another key, including when unsigned sources are allowed
    - an unsigned release (allowed only with `AllowUnsignedRelease`)
    - a supplied digest that disagrees with the signed one
    - a tarball not listed in `SHA256SUMS`
    - a plain binary
    - an unusable pinned file (fail closed)
  - Other tools are unaffected by the pin.
