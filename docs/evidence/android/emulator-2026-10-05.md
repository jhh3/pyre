# Android end-to-end: physical Pixel 10 Pro (partial) and emulator (2026-10-05)

Package W-android-e2e, branch `w-android-e2e` (based on main 5652a40). Covers A18 and the Android parts of A04, A08
and A09.

**Read this first.** Most steps ran on an **Android emulator, not a physical phone**. A physical Pixel 10 Pro was
attached for about 15 minutes and was then taken back by the owner. The steps that ran on it are marked
**[phone]**. Everything else is **[emulator]**. **No FCM** was used anywhere. Notifications came through the app's
own path: hub-stream mode, a foreground service that holds `/v1/events/stream`. All data is synthetic.

## A04 (Android part, plus artifact reference)

The shell peer ran this from its own pane:
`pyre send <mock> 'Synthetic review request…' --attach ver_01M46SJ2VM…(notes v2) --thread thr-pixel-a04 --request-ack`
→ `msg_01M46SRPW25B…`. Stored, then runtime accepted (mock evidence).

The mock peer replied with its own session credential (`pyre send --reply-to msg_01M46SRPW25B… --attach <same
version>`) → `msg_01M46SSCAXAK…`. A mock agent has no process of its own, so the harness read that session's
token from the isolated node DB into the environment only. The reply was stored. The shell has no `input.queue`,
so its runtime state is `rejected (unsupported …)`, and the shell read it with `pyre inbox`. The request's ack
became `replied (msg_01M46SSCAXAK…)`.

## Defects found and fixed (branch `w-android-e2e`)

1. **Web terminal refused on a real device** [phone]: `first frame must be {"type":"auth","ticket":...}`. The
   TerminalView lays out right after `connect` and sends a resize. OkHttp queues frames sent before the handshake
   and writes them first, so the relay saw the resize before the auth frame. The JVM test had no view, so it never
   hit this. Fix: `TerminalSocket` buffers input and folds resizes into the auth frame until auth is sent. Test:
   `TerminalSocketTest.resizeAndInputBeforeOpenNeverPrecedeTheAuthFrame`.
2. **Screens never refreshed** [phone]: session state stayed "Starting", delivery facts stayed stale, and the
   Sessions list kept "Cached · offline" after the hub returned. Also, a reply queued while offline did not replay
   while the screen stayed open, and the "Hub unreachable" banner stayed up after a successful replay. Fix: the
   Sessions, Inbox, session detail and message screens refresh every 5 s **while resumed** (nothing runs in the
   background). The session-detail poll appends newer transcript entries and replays pending sends.
   `Repository.flushOutbox()` marks the hub reachable after a replay that delivered something. Measured on the
   emulator: a CLI message appeared in the open session in 2.6 s, and after a hub restart the queued reply was
   stored once and the banner cleared in 2.6 s. Tests: `SessionDetailViewModelTest.pollReplaysTheOutboxOnceAndClearsThePendingNotice`,
   `IdentityAndHealthTest.successfulOutboxReplayClearsUnreachable`.
3. **A04 identity missing on Android** (above). Fix: `domain/Identity.kt`. Message cards and the message screen
   show From / To (`<title> (session:<id>)`, `owner (<client>)`), thread, reply-to, reissues, ack reference and
   attachments, with links to the referenced message and artifact version. The session screen lists both
   directions (`box: "all"`). The TUI message detail now also lists attachments
   (`TestMessageDetailShowsAttachments`).
4. **An arbitrary file could not be kept** (defect in the A09 table). Also, the app never said that the bytes were
   digest-verified. Fix: a "Verified: N bytes match the published SHA-256" banner, plus "Open with…" and
   "Save a copy…" (Storage Access Framework) for externally opened types.
5. Backend (test support): the mock adapter's `[mock:approval]` / `[mock:question]` markers
   (`TestAdapterMarkersRaiseRequests`).

Verification: `go vet` and `golangci-lint` (linux + darwin): 0 issues. `go test -p 4 ./...`: exit 0 (55 packages
ok). Gradle `testDebugUnitTest`: 90 tests, 0 failed (3 skipped: the mock/real/protocol hub ITs need their
scripts). `lintDebug`: successful.

## Not verified / limitations

- **Physical device**: only install, pairing, the same-key update with data, outbox survival, launch, read/reply
  and the (failing) terminal ran on the Pixel. Notifications, screen-off, Doze, approvals, questions, artifact
  review, document read, A04 views and all fixes ran **only on the emulator**. No real-hardware StrongBox or
  Keystore inspection was possible (the app is not debuggable). The migration was confirmed on the phone only
  indirectly: the app still authenticated after the update.
- **The fixes are in signed 0.2.2** (rc5 dist), but 0.2.2 has not run on any device yet. These checks still need
  to be repeated on the phone with it: terminal, live refresh, A04 views, save-a-copy. The emulator results for
  the fixes came from a debug build of the same commit.
- Screen-off was measured over minutes, not 30+ minutes. Forced Doze stands in for natural Doze. No network
  switch. No FCM (the `fcm` flavor was not built). No Twingate.
- Tapping a *question* notification once brought the app to its last screen instead of the request (the
  tap may have landed on the auto-grouped summary). Not reproduced. Opening it from the Inbox worked.
- The CLI prints an owner principal as `owner` without the client name. Android and the TUI include it
  (`owner (Android …)`). The identity is the same; the CLI is less detailed.
